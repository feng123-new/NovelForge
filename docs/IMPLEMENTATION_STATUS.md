## Architecture decisions

- The Web UI remains a client of the same REST/SSE service and does not duplicate Engine behavior.
- Components use one typed API Client so same-origin behavior, idempotency and structured errors cannot drift per page.
- The singleton client resolves the ambient browser `fetch` per request, allowing instrumentation without weakening explicit test injection.
- Foundation persistence is a validated request snapshot; Phase 9 will attach durable execution through the existing engine/event boundaries.
- Chapter collection metadata is bounded and deterministic; full content, versions and diff remain Phase 8 work.
- Models expose public registry metadata only; provider credentials remain outside the Web contract.
- Lockfiles, embedded output and dependency inventories are checked release inputs rather than hand-maintained artifacts.

## Database / migration changes

- No database migration was added in Phase 3.
- Foundation requests use atomic owner-only project files.
- Phase 2 `server.db`, durable events and idempotency records remain authoritative and unchanged.
