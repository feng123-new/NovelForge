# Phase 13B — 本地完整验收

本文件是可执行入口与人工验收方案，不是已执行结果。Phase 13A 交付候选程序与工具；Phase 13B 仍等待目标机器、真实模型和作品样本。记录 passed / failed / blocked / not run，不以跳过或缺少依赖冒充通过。

## 环境与证据

固定候选标签、commit、配置版本和样本。二进制烟测仅需 Python 3.10+；源码验证另需 Git、项目 go.mod 对应工具链（当前 1.25.5）、Node 22/npm。并发检测需要支持 race 的平台与 C 编译工具链；Docker/阅读器测试另行安装对应环境。

所有自动验证默认隔离 HOME、应用配置和工作区，不读取个人模型 Key，不自动执行付费模型。`verification-results/<timestamp>-<mode>/result.json` 保存源码/树、工具、范围、执行状态和日志索引；日志可能包含临时路径和测试样本，公开提交前检查。诊断分享使用应用的脱敏报告，不上传包含整书的项目备份或真实配置。

## 自动入口

在对应源码 checkout 根目录运行，每次 output 使用新目录：

```sh
python scripts/verify.py --mode doctor
python scripts/verify.py --mode quick
python scripts/verify.py --mode full
python scripts/verify.py --mode recovery
python scripts/verify.py --mode scale
```

Windows 可用 `py -3` 代替 `python`。Python 3.10+ 为工具要求，不是运行 novelforge.exe 的要求。

| 模式 | 精确范围 |
|---|---|
| doctor | 工具可用性与版本信息；不自动安装/升级系统工具 |
| quick | 实际入口构建、Phase 9–12 关键命名短流程、迁移与 OpenAPI、指定前端测试/类型/产物重现、真实二进制无模型烟测 |
| full | 全量 Go/vet、核心 race、完整前端测试及入口烟测；不含其他平台/付费模型/规模专项 |
| recovery | 已有人工定稿、重写中断、导入分析与恢复，以及 ScenarioB 权威边界回归 |
| scale | 既有十万事实时序索引 + 显式 100/500/1000 章合成版本/调用统计/备份样本；不生成千章小说 |
| smoke | 对指定发行二进制启动新工作区，检查 HTTP、静态页面、项目、统计、备份；不调用模型 |

`--skip-frontend` 是明确的部分验证，报告保留未执行说明；不能用于候选版发布门禁。没有工具时返回 blocked 或失败，不生成通过结论。完整自动脚本只代表该模式的约定范围，不能代替下面的人工和真实模型验收。

在解压包中可以单独运行：

```sh
python scripts/smoke_candidate.py --binary ./novelforge --report smoke-result.json
```

Windows 参数为 `--binary .\novelforge.exe`。完整源码测试应使用标签对应的源码，不要在仅含二进制的压缩包里运行 go test。

## 人工与故障验收矩阵

| 场景 | 必须观察的结果 |
|---|---|
| 默认入口与缺失配置 | Web 可以管理本地项目；未配置模型的操作不可伪装成功；明确启动才产生新付费调用 |
| 新建小说到两章定稿 | 基础设定、计划、上下文、草稿、事实提案、审核、人工批准、定稿/检查点和下一章均关联正确 |
| 暂停/停止/重启 | 暂停在步骤边界生效；停止不能被后续暂停覆盖；不因旧执行者或重复批准产生新定稿 |
| 人工修改前章 | 候选不直接成为权威；接受定稿后正文、事实、账本、索引/重建一致；旧计划失效并提示处理 |
| 模型结果已存而后续写入失败 | 重放持久化结果，不重复提交事实；持久化前的远端计费不确定明确保留 |
| 预算、未知用量、fallback | 每次显式尝试单独计数，重放不新增消费，未知不显示为免费；达到限制后不发下一请求 |
| 导入与恢复 | 上传无调用、分析需确认；断点可继续；未接受前无 Active Final/Truth；恶意/损坏归档拒绝 |
| 升级与回滚 | 升级前像可读取，旧迁移校验和不变；旧二进制与旧数据组合在新工作区验证 |
| 导出与阅读器 | 草稿/缺章/未完成提交拒绝导出；TXT/MD/EPUB 保持章节顺序，目标阅读器文本与目录可用 |
| 容量与长期使用 | 记录各规模查询时间、内存、DB/备份大小；不得超出备份展开/压缩上限而没有明确错误 |

模拟进程中断必须在副本中进行。`kill`/强制终止不等于真实断电验证。不要对唯一正式作品做磁盘写满、删除、并发和故障注入。

## 真实模型分级验证（手动且显式付费）

先选一个实际使用的模型配置，新建独立测试项目，在 Diagnostics & Cost 配置准确单价、小额预算和调用次数限制。先写 1 章、逐章审阅；核对结构化输出、上下文、角色视角、费用及导出，再扩大到 3–5 章。手工比较服务商用量/账单，不假定本地估算等于扣费。

短链路稳定后，选择代表性题材扩大到 20–50 章，分别记录工程错误率和文学质量（人物一致性、节奏、重复、伏笔、风格）。是否扩大百章规模由预算和结果决定。合成规模测试不产生同等模型成本，也不能证明文学质量。此仓库没有自动调用个人模型进行付费全量测试的快捷按钮。

## 候选版循环与稳定发布门槛

每个问题记录：候选标签/commit、系统架构、配置摘要（无密钥）、复现步骤、预期/实际、脱敏错误码/trace、影响范围和回归结果。通过 PR 修复后发布新的 rc 编号，旧标签和原始失败证据不改写。

阻塞稳定发布的问题包括：数据或版本丢失、接受事实重复提交、人工定稿被覆盖、恢复破坏项目、凭据泄漏、失控模型请求、默认主流程不可用。非核心排版或已公开限制可以另行评估，但不能隐藏。最终通过范围必须绑定最后发布的精确源码和目标平台，不能拿早期候选测试替代后续已修改版本。
